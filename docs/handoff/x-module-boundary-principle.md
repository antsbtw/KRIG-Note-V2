# 原则：X 是可装卸模块

> 用户 2026-09-30 拍板，**本文件是 X 重建的第一性约束**：
>
> 「先建立一个原则，就是 x 模块是一个完全独立的模块，可以很简单的卸载和安装。
> 　底层 web 的控制、输入、输出部分函数共用。只有属于 x 的特殊部分函数才为它特有。」

⭐ 这不是一句方向性的话，下面每一条都要能写成守卫。
**写不成守卫的条款不算条款** —— 靠自觉守的边界只会悄悄烂掉（本仓反复吃亏的形态）。

---

## 一、判据：怎么算「很简单的卸载」

⭐⭐ **唯一判据 —— 删掉 X 只需两个动作：**

```
1. 删一个目录
2. 删一行注册
```

然后：`tsc` 0 错、单测全绿、`vite` 起得来、app 里没有任何残影。

⚠️ 这条判据不能靠「看起来是这样」通过，必须**真的删一次**。
推倒 X 那次实测到：删完代码，四类残留仍在（见 §四）。

---

## 二、共用的（底层 web）vs 特有的（X）

用户原话的切分：**「控制、输入、输出」共用；「只有属于 x 的特殊部分」特有。**

### 共用 —— `web-capability/` 6683 行，X 只是使用者

| 段 | 它是什么 | 为什么共用 |
|---|---|---|
| `page/` | **控制**：goto · ready · scrollUntil · 页面租约 | 翻页滚动对 X/AI/浏览器同一回事 |
| `input/` | **输入**：tap · press · type · 合成 paste | 往输入框写字不分厂商 |
| `net/` · `raw/` | **输出**：载荷捕获 · 原始留痕 | CDP 通道与留痕格式与业务无关 |
| `dom/` | 读页面 | 同上 |
| `trace/` | 诊断 | 同上 |
| `wiring/` | 接线（注册表） | 底座认识的是「注册入口」，不是 X |

⭐ 共用不等于「X 不许有自己的参数」：
`scrollUntil` 的停止判据、`goto` 的 arrival 闸 —— **机制在底座，判据由 X 传参**。
这是「共用」与「为 X 定制」的分界线。

### 特有 —— X 自己的目录

只有**与 X 这个平台绑死**的才算特有，判据是「换成另一个网站会不会失效」：

- X 的 GraphQL 载荷解析（`SearchTimeline` / `UserByScreenName` 的字段路径）
- X 的语义页面表（`x.home` / `x.profile` / `x.status` / `x.articles`）
- X 的锚点（handle / tweetId 怎么拼成 URL）
- X 的库表与 schema
- X 的视图、IPC 通道、业务流程

## 三、允许的连线（⭐ 每条都是一条守卫）

```
        ┌─────────────────────────┐
        │   主程序 / 宿主          │
        │                         │
        │   ① 一行注册 ──────────┐│
        └────────────────────────┼┘
                                 ↓
        ┌────────────────────────────────┐
        │  X 模块（一个目录，自带一切）    │
        │  视图 · IPC · repo · schema     │
        └───┬────────────────────────┬───┘
            │ ② 用能力              │ ③ 推自己的表
            ↓                        ↓
        ┌────────────────────────────────┐
        │  web-capability（底座）         │
        │  控制 · 输入 · 输出 · 留痕      │
        └────────────────────────────────┘
```

### ✅ 允许

| # | 连线 | 守卫怎么写 |
|---|---|---|
| ① | 主程序注册 X，**仅一行** | 扫主程序：提到 X 的地方 ≤ 1 处 |
| ② | `X → web-capability` | 无需守卫（这是设计意图） |
| ③ | `X` 启动时把自己的**表**推给底座 | 已有：`registerAnchorTable` / `registerPageTable` |
| ④ | `X → 自己的库` | 扫 X：只准 `getXDB` |

### ❌ 禁止

| # | 禁止 | 为什么 | 守卫怎么写 |
|---|---|---|---|
| ⑤ | 底座 `import` 业务 | 底座离开业务就不能构建 | **已有** `layering-direction.test.ts` |
| ⑥ | **主程序 `import` X** | X 拔不掉 | ⚠️ **缺** —— 见 §五 |
| ⑦ | X 的视图注册散在 renderer | 删目录后留残影 | 扫 `renderer/index.tsx` |
| ⑧ | X 的 IPC 混进全局 channel 表 | 通道表长在别处，删不掉 | 扫 `channel-names.ts` |
| ⑨ | X 的 repo 混进 `db/` | schema 跟着主库走 | 扫 `db/` 目录名 |

## 四、⚠️ 装卸不只是代码 —— 推倒时实测到的四类残留

删完 X 的 .ts 文件之后，这些**仍然在**：

| 残留 | 症状 | 教训 |
|---|---|---|
| slot 绑定 | 右栏显示「x-workbench-view（待 L5 component）」 | 状态存在别处，代码删了它还在 |
| 副作用 import | vite 运行时炸 | ⭐ `import 'x'`（无 from）**tsc 查不出来**，栽过一次 |
| 通道表 / preload | 通道注册残留 | 通道名长在全局表里 |
| 库表 / schema | 19 张表结构还在 | schema 得跟着模块走 |

→ **新模块必须让这四类全部跟着目录走。**

## 五、现状对账（2026-09-30 实测，不是推断）

### ✅ 已经守住的

- 底座**零业务 import**：所有非相对 import 只有 `electron` / `node:path` / `node:fs`
- ⑤ 有守卫：`tests/web-capability/layering-direction.test.ts`
  钉了三层（web-capability / executor / flow）+ 注册入口 + 已知债只减不增
- 底座里的 X 字样**全是注释**（记某个原语抄自哪里），不是代码依赖

⭐ 我 2026-09-29 在上一份文档里说「依赖方向没有守卫钉着」—— **说错了**，
那条守卫 2026-09-15 就建好了。更正在此。

### ✅ 缺口已补（2026-09-30，commit e6329fa6）

⑥「主程序不许 import X」**已有守卫**：`tests/modules/x-module-detachable.test.ts`（10 条）

钉两个数：
1. X 目录之外，认识 X 的地方 ≤ 1（那一行注册）
2. 四类残留（视图注册 / IPC 类型 / shared 目录 / 共用层）必须跟着模块走

⭐ 已按 `feedback-verify-guard-can-fail` 做注入验证，**三种都试过**：

| 注入 | tsc | 守卫 |
|---|---|---|
| 具名 `import { x } from '@platform/main/x/…'` | 红 | ✅ 红 |
| ⭐ 副作用 `import '@capabilities/x-extraction';` | **0 错** | ✅ 红 |
| 无关 `box.x` / `xz-util` / `https://x.com` | — | ✅ 不误伤 |

⭐⭐ 第二行是关键：**tsc 看不见副作用 import**，而它正是删 X 时两次炸掉 vite 的那一种。
守卫抓到了编译器抓不到的东西 —— 这是它存在的唯一理由。

⚠️ 注入验证还抓出守卫**自己的 bug**：初版判据要求路径段后面跟 `/`，
于是末尾无斜杠的 `'@capabilities/x-extraction'` 整条逃过。已改成「`/` 或引号」。

### ⚠️ 守卫第一次跑就是红的 —— 上一版「已彻底归零」是错的

我 2026-09-29 报告 X 已归零。守卫当场证否，实测挖出：

| 残留 | 量 | 形态 |
|---|---|---|
| 全局 channel 表里的 X 通道 | **62 条，其中 61 条零 handler** | ⭐ 名字在、两头空 |
| preload 的 X 方法 | 11 个 + 整个 `xTimeline` 对象（152 行 / 51 通道） | X 编织进宿主 API |
| `electron-api.d.ts` 声明 | 11 条 + `xTimeline`（229 行） | 同上 |
| 孤儿文件 | 3 个 / 381 行，**零消费点** | 删代码时漏下的 |

⭐ 61 条零 handler 的通道 = 又一次 `project-x-tweet-inbox-is-dead-table` 的形态：
preload 有发送口、通道表有名字、主进程没人接、renderer 没人调。
**点了没反应的管子焊在宿主 API 上。**

⭐ 这印证了 §一 的判据不能靠肉眼：「看起来归零」与「真的归零」差 959 行。

### ⭐ 一个例外，已注明理由

`X_OPEN_TWEET_REQUEST` **保留**。它名字带 X，但属于 **note 的 tweet block**：
note 里嵌的官方推文卡片点「Read replies」时，`window.open` 冒到宿主 webContents，
Electron 默认会开一个无登录态的裸窗口飞出工作空间（`window/main-window.ts:94`）。
X 模块卸载后这条依然要在。

⚠️ 不写清楚，下一个人会当成漏删的残留删掉 —— 判据是
**「X 卸载后这件事还需不需要」**，不是「名字里有没有 x」。

### 已知债（不是 X 引入，别顺手改）

`web-capability/dom/ai-scripts.ts` → `ai/inject-scripts/` 三处 import。
与锚点表同一种倒置，正解也一样（AI 启动时把脚本推进来）。
已被 `KNOWN_DEBT` 锁死、只减不增。
