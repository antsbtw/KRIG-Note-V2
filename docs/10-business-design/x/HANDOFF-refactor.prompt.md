## 3. 如何验证(这个仓库的特殊之处)

### 查真实数据

app 开着时,SurrealDB 在 `127.0.0.1:8533`:

```bash
curl -s -X POST http://127.0.0.1:8533/sql \
  -u "root:<密码见 app 启动参数>" \
  -H "Accept: application/json" -H "surreal-ns: krig" -H "surreal-db: krig_x" \
  -d "SELECT count() FROM x_tweet GROUP ALL;"
```

⚠️ app 关掉 SurrealDB 就退出,查不到 ≠ 数据没了。
⚠️ **活动爬虫(campaign)跑在另一台 Windows 机器上**,本机查它恒为 0,那是预期。

### 守卫的正确用法

```bash
npx vitest run tests/x/          # 全量
npx tsc --noEmit -p tsconfig.json # 类型(注意:XInboxView.tsx:773 有一条既有错误,与你无关)
```

**写完守卫必须注入违规验证它会红** —— 这个仓库有过「掏空核心函数测试仍全绿」的教训。

### 别踩的验证陷阱

- 用 Python 改含中文的文件时注意编码(踩过:UTF-8 被写坏,tsc 报 Invalid character)
- 测注入浏览器的脚本要**真的求值**再 parse(模板字面量会吃掉转义)
- 守卫比对源码前**先剥注释**,否则会被自己的说明文字骗过(踩过两次)
