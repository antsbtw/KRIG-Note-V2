# 回复关系 —— 设计与实施方案

> 立于 2026-09-02。前置:[数据获取能力勘查](data-acquisition-capability-survey.md) §2.4
>
> 业务定位(用户口述):主线是「找到需要买 VPN 的人 → **回复他们** → 跟踪点击 →
> 按买/没买分流画像」。**回复关系是这条主线的第一环。**

---

## 1. 为什么现在能做:权威字段已在载荷里

✅ **实测**(2026-09-02,`UserRepliesTimeline` 真实响应):
40 条推文对象中 22 条带回复字段,形如:

```
推 2095103100344275234
  in_reply_to_status_id_str = 2095055095004340586   ← 父推 id
  in_reply_to_screen_name   = cassy29407            ← 被回复者 handle
  in_reply_to_user_id_str   = 1780943891018993664   ← 被回复者 id
  conversation_id_str       = 2095055095004340586   ← 会话根
```

→ **不需要任何推断**。此前从 DOM 猜连接线像素 / idx 相邻 / 正则匹配的三套判据
**全部作废**(教训见能力勘查 §1.2、§2.4)。

### 1.1 ✅ 关键验证:能对上库里的已采纳推文

实测一次采集:
- 抓到 **27** 个不同的父推 id
- 库里匹配到 **14** 条
- **其中 11 条是 `accepted = true` 的已采纳推文**

→ 「我回复过哪些采纳的线索」**可以直接算出来**,这正是此前
   「已回复标绿」缺的数据源(当时 `replied` 全库为 0,因为
   `markReplied` 只有手动按钮会调,而真正发回复的 `x-write.ts` 不落库)。

## 2. 数据模型(对照数据模型总纲)

### 2.1 字段扩充 —— `x_tweet`

现状只有一个 `in_reply_to`(且是 DOM 取错的产物,全库为 0)。
按**实体优先、关系第二性**,回复关系是推文自身的属性,不建边表:

| 字段 | 类型 | 语义 |
|---|---|---|
| `in_reply_to`(已有) | `option<string>` | **改为存父推 id**(原语义是 URL,从未被正确填过) |
| `in_reply_to_user` | `option<string>` | 被回复者 handle(归一化) |
| `conversation_id` | `option<string>` | 会话根 id —— n 层关系靠它 GROUP BY |

> 不新建 `x_reply` 边表 —— 方案 §4.1(5) 已定「先不建任何边表」,
> 当前万级量 SQL 足够。真慢了再物化派生表。

### 2.2 `replied` 的语义修正

**现状是错的**:`replied` 只由手动按钮设置,记录的是「我点没点过那个按钮」,
而非「我是否真的回复过」。用户明确说过自建回复功能不好使、没在用。

**改为**:由**采集到的客观事实**推导 ——
自己的推文里 `in_reply_to = X` 存在,则 `x_tweet[X].replied = true`。
- 抓到即事实(与方案 §2 的判据一致)
- 手机上回的、网页上回的,一律算数
- 手动按钮保留(可覆盖),但不再是唯一来源

## 3. 实施步骤

| # | 内容 | 说明 |
|---|---|---|
| 1 | **CDP 拦截落库** | 复用 `x-payload-inspector` 的机制,从 `UserRepliesTimeline` / `HomeTimeline` 等响应里解出推文对象直接入库 —— 比 DOM 抓取字段全得多 |
| 2 | schema 1.0.1 | 加 `in_reply_to_user` / `conversation_id` 两字段 + 索引 |
| 3 | 回填 `replied` | 用已抓到的父推 id 反标已采纳推文 |
| 4 | UI | 「已回复」按已落库的事实显示(接上此前的「已采纳标绿」) |

### 3.1 ⚠️ 边界:抓多少才算全

B′ 诊断实测:滚 60 轮只覆盖 **3.2 天**,未到底(账号 1183 条)。
→ 首次回填能覆盖的回复**有限**,不能声称"全量"。
   策略按用户此前拍板:**首次 7 天 + 之后增量续跟**(滚到遇见已知 id 即停)。

## 4. 不做 / 待定

- **不做**链接点击归因 —— 不在 X 能力范围,需官网侧埋点(`ref=tw_*` 参数已在用)
- **不做**画像形态设计 —— 用户明确「画像需要迭代」,本轮不设计
- **待实测**:`Retweeters` 是否可用(促转发功能依赖它)
