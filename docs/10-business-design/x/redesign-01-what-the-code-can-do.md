---

## 0. 一句话总览

X 模块现在能做 **五件大事**,但它们**不是一条流水线,而是三条独立的链** ——
这正是「觉得乱」的结构性原因:

```
链 A(自动跑)   采集 → AI 判断 → 进收件箱          ← 定时器驱动,无人值守
链 B(人工跑)   人工采纳 → 拟回复 → 填进 X          ← 全靠人点,一步都不自动
链 C(自动跑)   通知采集 → 活动留言 → 推送          ← 定时器驱动,与 A/B 不交汇
```

> 三条链**共用一个界面、共用几张表,但没有共同的业务主线**。
> 后面讨论边界时,这是第一个要拍板的:**它们该合成一条,还是本就该分开?**

### 3.7 ⭐ 配方能力的实际边界(用户特别问的)

**模板有 4 种,但只有 1 种有专属逻辑**:

| 模板 | 状态 |
|---|---|
| `help-wanted` | ✅ **唯一在用**(拼 helpSignals 求助信号词) |
| `trending` | ⚪ 类型里有,**无专属处理逻辑** |
| `vip-tracking` | ⚪ 同上 |
| `custom` | ⚪ 同上 |

**代码里的种子配方只有 2 条**,都是 `help-wanted`:

- **VPN求助-英文**:`VPN / proxy / bypass GFW / censorship / blocked / shadowsocks / clash / v2ray / xray`
- **VPN求助-中文**:`VPN / 翻墙 / 科学上网 / 梯子 / clash / v2ray / shadowsocks / 连不上 / 不能用`

> ⚠️ 「回国需求」中英两条是**只在库里加的,代码里没有** —— **重建库会丢**
> (记忆 `project-x-return-to-china-recipes`)。同理,英文关键词的精确率调整也只在库里。

**能配的筛选条件**:关键词(OR)· `from:账号` · 求助信号词 ·
`min_faves` · `min_retweets` · `lang` · 时间范围 · `latest/top` ·
要不要连回复(`filter:replies`)。

> ✅ 实测过:`include:replies` **X 已不支持且静默返回 0 条**,必须用 `filter:replies`;
> 裸 `from:` 本身就带回复(12 条里 11 条),**「只要原创」反需额外过滤**。

## 6. ⚠️ 「数据库组织与分析」—— 有组织,几乎没有分析

用户列的第 6 条需要**纠正**。实测 `tweet-inbox-repo.ts` 的 19 个导出:

| 类别 | 函数 |
|---|---|
| **写入** | `upsertTweet` / `insertFilteredOut` / `insertFeedback` / `setTranslation` / `setParentContext` |
| **状态流转** | `markAiJudging` / `recoverStuckAiJudging` / `updateVerdict` / `applyHumanVerdict` / `markReplied` |
| **查询** | `queryPending` / `queryInbox` / `getTweetIdSet` / `queryFeedbackSamples` / `queryMissingTranslation` / `getGenuineAiVerdict` |
| **统计** | `countPending` · **`getFeedbackStats`** ← **唯一算「分析」的** |
| 维护 | `cleanExpired` |

> **结论:现在有的是「组织」(表结构 + 状态机),不是「分析」。**
> 唯一的分析是 `getFeedbackStats`(近 7 天 Gemma 建议采纳率 / 捞回漏判数)。
>
> 你想要的那类分析 —— **哪类人回复率高、哪条配方产出好、库里分布如何** ——
> **现在都得手写 SQL 查**,代码里没有。

## 9. UI 现状(讨论重整的起点)

**`XInboxView.tsx` 2199 行,7 个子视图挤在一个文件**:

```
L103   RecipeEditModal        配方编辑弹窗
L335   RecipeManagerView      配方管理
L1288  CampaignConfigView     活动配置
L1662  BlockedManagerView     屏蔽名单
L2034  CaptureMonitorView     采集监视器
       + ReplyDraftsView(回放验证)/ WatchlistView(追踪名单)在别的文件
```

**顶栏是 8 个平铺按钮**:

```
[刷新] [AI 判断] [🧵 预取资料] [🔁 回放验证] [⚙ 配方] [👁 追踪名单] [🚫 屏蔽名单] [⚙ 活动配置]
```

**收件箱内部还有 5 个视图切片**:待判 / Gemma建议 / 漏判抽查 / 已确认 / 全部

### 9.1 观察到的问题(待讨论,不是结论)

| 现象 | 疑问 |
|---|---|
| 8 个按钮平铺,**两个都叫「⚙」** | 配方和活动配置是同一层级吗? |
| 「AI 判断」「预取资料」是**动作**,「配方」「名单」是**页面** | 动作和导航混在一排 |
| 子视图切换是**整页替换** | 从配方回收件箱要点返回,**不能并排看** |
| 收件箱里再分 5 片 | 两层切片,人要记住自己在哪 |
