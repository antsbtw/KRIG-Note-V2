## 2. 三条流程(用户 10-16 确认:「正确」)

### 流程 A:找蓝V → 求关

```
① 搜索   配方「蓝V互关」(互关必回 / 关注必回 / #互关 …)          复用:配方搜索
② 提取   推文 + 作者进库(蓝V、关系标记都带着)                     复用:搜索提取
③ 分析   候选 = 蓝V ∧ 我没关注 ∧ 没排除 ∧ 有互关倾向                新:分析规则
         倾向依据:Bio 命中句 / 帖子命中句(先算法,后 AI),存原文
④ 过目   候选列表,依据原文;不要的右键排除                         复用:人页 + 排除
⑤ 执行   关注他 + 回复他那条求互关帖                               关注:新(取关镜像);回复:见流程 C
⑥ 核对   动作记录 + 执行后读他主页确认                              复用:x_action_log + 点人核对
⑦ 回访   关注 N 天他没回关 → 进「我关注·他没回关」                  复用:现有取关工作流
```

### 流程 B:已互关蓝V的互动维护

```
① 采集   我对他:采我自己的号(帖子/回复/转发)                       复用:后台采集(把自己当一个人)
         他对我:我推文下的回复 / 点赞者 / 转发者                     新:采集
② 分析   4878 人分四组:双向都有 / 只有我对他 / 只有他对我 / 从没互动   复用:朋友圈算法反向
③ 策略   「从没互动」→ 进互动队列:挑他最近一条帖子去回复             新:挑帖规则
④ 执行   回复                                                      同流程 C
⑤ 复查   下轮采集后看他回应了没,回应了就移到「双向」                 复用:② 重算
```

### 流程 C:回复(A、B 共用,唯一真正新增的能力)

```
阶段 1 学习   范例来源:你号上已有的回复(流程 B① 顺带采到)
              + 你在系统里每一次手写/修改的回复
阶段 2 建议   AI 照你的范例拟稿 → 你修改 → 你点发送
              每条记:AI 原稿 / 你最终发的 / 改了多少
阶段 3 放手   按场景分开统计(求关回复 / 日常互动回复各算各的)
              达标 → 该场景的「AI 自动回复」开关才能打开
              打开后仍守:上限 / 间隔 / 出异常就停 / 每条留记录
```

## 3. 已拍板的决定

| 决定 | 出处 |

| **放手门槛:同一场景 ≥50 条且 ≥80% 原样通过** | 用户 10-16:「同意不变」 |

放手门槛的含义(给人看的版本):AI 拟了 50 条,你 42 条一字没改就发了 = 84% ≥ 80% → 开关变得**可以**打开(打不打开仍由你)。
没发/跳过的不算分母。至少 50 条是怕样本太少碰巧;80% = 十条最多改两条。

## 4. 我的判断(未逐条拍板,实施时如有分歧以用户为准)

- **关系按号存一行**(号 rest_id × 人 rest_id → 他关注我 / 我关注他 / 观察时间),**不在人表上按号加列**:效果一样,第三个号零改表。
  用号的**数字 id** 不用 handle —— antsBTW → otun_myvpn 改名就是反例。
- **推文载荷里的关系标记是「看的那个号」的视角**(following / followed_by)→ 写入时必须知道是哪个 ws 采的,
  按 `x_ws_account` 换成号;拿不到号就**不写关系、留痕**,不猜(fail loud)。
- 回访 N **默认 7 天**,做成 `x_setting` 可设变量(同取关每日上限的做法)。门槛 50 / 80% 也做成可设变量。
- 放手统计**按场景分开**:求关短回复会很快达标,不该带着日常互动回复一起放手。
- 倾向判断三来源分开存(人 > AI > 算法,同「排除」的写法),**依据原句必存** —— 否则事后说不清为何求关他。
- `filter:blue_verified` 搜索语法**未真机验**,M1 先验它。

## 7. 实施时的铁律(本仓已踩过的)

- 关系/动作的保护措施是 AI 接管的前提:节奏限制、异常即停、只追加动作记录(谁决定/对谁/原因/结果/时间)、执行后核对

- 模块级状态每进程一份:renderer 登记、主进程读会恒空(后台 runner 事故)

- X 模块可装卸:删一目录 + 删一行,不往宿主/能力层塞 X 业务
