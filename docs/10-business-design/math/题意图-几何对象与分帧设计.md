# 题意图：math-visual 加「几何对象」与「分帧」

> 状态：设计稿，未开工 · 2026-11-06
> 样本题：Andy / Betsy 骑车题（Andy 1:30 向北 8 mph，Betsy 2:30 向东 12 mph，何时离出发点一样远）

## 一、为什么做

老师讲题的第一步不是解法，而是**用图把题意讲清楚**：先画一个人做了什么，再画另一个人做了什么，最后画题目要求什么。8 种解法（追及 / 列表 / 最小公倍数 / 方程……）都站在同一张题意图上，只是各自往图上加东西。

题意图的本质是**带坐标、带比例尺的几何图 + 分步展示**，不是函数图，也不是自由画板。所以放在 math-visual 里长，不进画板（画板以后可以嵌 math-visual 做讲义排版，不在本稿范围）。

### 用户定下的效果（2026-11-06）

用户选了「两者都要」：
- **上课 / 编辑**：同一张图逐帧叠加，`◀ 1/3 ▶` 翻页，每帧配一句题目原文。
- **讲义 / 导出**：自动展开成几张图并排。

## 二、样本题的三帧（验收用的真实样本）

**帧 1｜Andy 做了什么** — 「Andy leaves Mathville at 1:30, due north, 8 mph.」
```
        北
        ↑
     16 ┼  3:30
      8 ┼  2:30
        │  Andy 每小时 8 英里
        ●  Mathville 1:30
```

**帧 2｜Betsy 做了什么** — 「Betsy leaves from the same point at 2:30, due east, 12 mph.」
```
      8 ┼ ◐ Andy（此刻已在这里，虚影）
        ●────────┼────────┼──→ 东
               12       24
```
两个方向**同一比例尺**，Betsy 一格（12）明显比 Andy 一格（8）长。

**帧 3｜题目要求什么** — 「At what time will they be exactly the same distance from their common starting point?」
```
        ● Andy
        │╲  ✗ 不是两人之间的距离（虚线打叉）
        ●──● Betsy
        以 Mathville 为圆心的圆 —— 同时落在圆上 = 一样远；时间 = ？
```
题意图里不出现答案。

## 三、要补的能力

现状（读代码确认）：
- math-visual 只能存**函数曲线** + **挂在曲线上的标注**，没有独立的点 / 线段 / 箭头 / 圆 / 文字。
- Mafs 0.21 本身就有 `Point / Line.Segment / Vector / Circle / Polygon / Text`，capability 已经在用其中几样 —— 渲染层不缺，缺的是数据模型和编辑入口。
- inline 只显示一张 `thumbnail`（全屏退出时导出的 SVG），不跑 Mafs。

### 3.1 几何对象（shapes）

五种：**点、线段、箭头、圆、文字**。

```ts
// driver types.ts（用户编辑数据）
type ShapeKind = 'point' | 'segment' | 'arrow' | 'circle' | 'text';
type Coord = [string, string];            // 表达式字符串，可引用参数（为以后时间滑块联动铺路）

interface ShapeEntry {
  id: string;
  kind: ShapeKind;
  at?: Coord;                             // point / text
  from?: Coord; to?: Coord;               // segment / arrow
  center?: Coord; radius?: string;        // circle
  text?: string;                          // text 内容；点/线的 label 也走这里（支持 $LaTeX$）
  color: string;
  style: 'solid' | 'dashed' | 'dotted';
  lineWidth: number;
  opacity?: number;                       // 虚影 = 降低不透明度
  ticks?: { step: number; labels?: string[] };  // 线段/箭头上按 step 打刻度，labels 依次标在刻度旁
  struck?: boolean;                       // 在中点画 ✗（「不是问这个」）
  frames?: { from: number; to?: number }; // 见 3.2；缺省 = 所有帧都显示
}
```

- 函数曲线 `FunctionEntry` 同样加可选 `frames`，后续解法帧要用。
- **表达式算不出来要报错显示在对象列表那一行**，不静默丢掉（不兜底）。
- 渲染：capability `MathHost` 新增 `shapes: ShapeSpec[]` prop，接的是**已求值的数字坐标**；driver 用现有 `createEvalFn` 求值。Mafs import 仍只在 `src/capabilities/math-rendering/`。

### 3.2 分帧（frames）

```ts
interface FrameEntry {
  id: string;
  text: string;          // 这一帧配的那句话（老师填，通常是题目原句）
}
// MathVisualData 新增
frames?: FrameEntry[];          // 缺省或空 = 单帧，行为与现在完全一致
frameThumbnails?: string[];     // 每帧一张 SVG，全屏退出时生成
```

- 对象在第 i 帧可见 ⇔ `frames` 缺省，或 `from ≤ i ≤ (to ?? ∞)`。这个判定写成一个纯函数，driver 和缩略图生成共用。
- 「逐步叠加」= 大多数对象只设 `from`；「这帧出现下帧消失」= 设 `to`（如帧 2 的虚影可以在帧 3 保留或隐去，由老师定）。
- 原 `thumbnail` 字段保留，**取最后一帧**（完整图）。所有现有消费者（X 长文内嵌图 `collect-renderable-blocks`、`note-to-article-plan`）零改动、行为不变。

### 3.3 编辑（全屏）

左栏在「函数列表」下新增两节：
- **图形对象**：列表（类型 / 坐标 / 颜色 / 出现帧）+ 画布点击添加：点 = 点一下；线段、箭头 = 点起点再点终点；圆 = 点圆心再点半径；文字 = 点位置后输入。添加后坐标写成数字字符串，可以再改成表达式。
- **分帧**：帧列表（增删、改那句话、调顺序）；画布上方 `◀ 第 i 帧 ▶` 切换编辑中的帧；在第 i 帧新增的对象默认 `from = i`。

### 3.4 inline 显示

- 有 `frames`：图上方显示当前帧那句话，工具栏多一组 `◀ i/n ▶` 和一个「展开」开关。
  - 翻页：切换显示 `frameThumbnails[i]`，纯 SVG，不跑 Mafs。
  - 展开：把 n 张图按宽度档位并排（窄时上下排），每张带它那句话。
- 当前帧序号、展开与否是**看的人自己的状态**，不写进 PM（不进 undo、不污染文档）；只有「默认展开」作为文档属性存 `canvas.frameLayout: 'step' | 'expand'`。

### 3.5 缩略图生成

全屏 `onClose` 现在只导出当前画布一张 SVG。改为：有 `frames` 时依次把渲染帧切到 1…n，每次等画面刷新（两次 `requestAnimationFrame`）后 `exportSelfContainedSvg`，收齐写 `frameThumbnails`；`thumbnail` = 最后一张。

### 3.6 导出

- X 长文等现有路径：仍用 `thumbnail`（完整图），不变。
- 讲义 / 打印（以后）：取 `frameThumbnails` + 每帧 `text` 按顺序排。本稿不做打印入口，只保证数据够用。

## 四·附　P1 实施记录（2026-11-06，分支 feature/math-visual-shapes-frames）

已做：
- capability：`ShapeSpec` 四类（点 / 线段·箭头 / 圆 / 文字）+ `host/ShapeLayer.tsx` 用 Mafs `Point / Line.Segment / Vector / Circle / Text` 画；`compute/shape-geometry.ts` 放刻度位置、方位、法向等纯计算；新 API `evalScalar(expr, params)`（算不出来返回原因，不兜底成 0）。
- driver：`ShapeEntry` 存 PM attr `shapes`（parseDOM / toDOM / node-view / 全屏读写四处都接了）；`shapes.ts` 放表达式 → 可画对象、新建、吸附、等比例、点击换算的纯函数。
- 全屏左栏新增「图形」（选种类 + 对象列表，画不出来的标红写原因）和「视图」（x/y 范围、等比例、网格、坐标轴、刻度数字）；右栏选中对象后编辑位置 / 标签 / 颜色 / 实虚线 / 线宽 / 虚影 / 刻度与刻度字 / 打叉。
- 点击：点、文字一下；线段、箭头、圆两下（第一下出灰点，Esc 取消）；落点按可视跨度吸附到 1/2/5×10^k。
- 有几何对象时允许删光函数（题意图不需要 x²）。

顺手修的两个旧问题：
1. 「视图」设置原来写了 `SettingsPanel` 却没挂到任何界面，全屏里改不了范围、关不掉网格。
2. 画布点击换算没算 Mafs 四周默认 0.5 单位边距（`viewBox.padding ?? 0.5`），点哪儿落哪儿有偏差；现在标注 / 切线 / 框选也跟着准了。

取舍（我的判断，非用户要求）：
- 文字只用 SVG text，不支持 `$LaTeX$`：MathHost 的 label 交互层按 DOM 顺序把 `.katex` 对到曲线 label，几何对象再出 `.katex` 会打乱；需要时另做。
- 「等比例」由 driver 按画布宽高放宽一个方向实现，没用 Mafs 的 `preserveAspectRatio: 'contain'`——后者会让点击换算对不上。

P1 追加（同日，用户真机试用后提出）：
- 「应该有放大和缩小的功能」→ 视口改由面板自管：滚轮以鼠标为中心缩放、移动模式拖动平移、画布右上 ＋ − ⤢（显示全部图形），停下后写回 x/y 范围。原「缩放后点击换算错位」随之消失。顺手修：「刻度数字」从来不显示（显式传 `labels: undefined` 盖掉 Mafs 默认）。
- 「还有选定对象和操作的能力吧？」→ 移动模式下点图形选中、拖动整体移动（算式坐标不动）；选中后出白色手柄（线两端 / 圆心与半径 / 面的顶点）可单独拖；方向键微调（Shift ×5）、⌘D 复制、Backspace 删除、Esc 取消选中。新增「面」（多边形）：逐个点顶点，点回第一个点或回车完成，可关填充。
- 「框选应该是选定元素进行操作吧…Mathville 这个点很难单击选中」→ 框选改成选图形：在空白处拉方框，**完全框住**的才选中（碰到就算会把从原点出发的箭头一起带上），Shift 追加；Shift+点击加选/去掉；⌘A 全选。多选后一起拖、一起微调、一起删、一起复制，右栏统一改颜色/实虚线/虚影。点的命中范围 12px，点旁边的标签也算点中。原「框选标注点」保留。
- 多选右栏：「既然选了两个图形，那就在右边列表这些选定的元素」→ 逐个列出、默认全部展开就地编辑；「整体修改」（颜色/线型/虚影）默认收起。
- 「复制删除用右键菜单好了」→ 右键画布上的图形或左栏列表一行：复制 / 删除 / 置顶 / 上移一层 / 下移一层 / 置底；右栏不再放这些按钮。
- 「cmd+Z 的取消操作没有生效吗？」→ 全屏面板拦下了按键，⌘Z 到不了 note 编辑器，且面板镜像的数据不会回退；改为面板自带撤销/重做（⌘Z / ⌘⇧Z），600ms 内连续改动合一步，缩放平移与切工具不算编辑、撤销时视图不动；输入框里的 ⌘Z 归输入框。
- 「还有一个图层的上下层关系没有」→ 图层顺序 = 数组顺序（越靠后越在上）；⌘] / ⌘[ 上移下移，加 Shift 置顶置底，多选整组；左栏列表改为越靠上越在前。
- 多选右栏改为「选中的元素从上到下直接排开、全部是完整编辑区」（用户：不要点选 tab）；原列表放在限高 300px 的容器里，第二个元素被挤到框外。
- 「标签 Andy 被挡住了，应该允许用户拖到合适的位置」→ 根因是 Mafs `<Text attach>` 的上下偏移是反的（attach 含 n 时往下偏），朝北箭头的标签正好压在箭头上。改为偏移自己算（`labelLayout` / `labelShiftPx`），Mafs 只做对齐；标签可在画布上拖动，偏移按屏幕像素存 `labelOffset`，右栏可复位。渲染（ShapeLayer）与命中（capability API `shapeLabelBox`）共用同一套布局。

## 四·附二　说明卡片：标签升级成「一小段 note」（2026-11-06 立）

**用户原话（2026-11-06）**：「标签应该是允许多行，而且最好能表达 note 中的各种 block 格式……解题时需要用各种文字表格来讲解已知求未知的过程，已知是什么？文字、公式、列表、图形。他们是互相转换的。」编辑方式用户选 **A：画布上双击卡片原地编辑**。

**效果**：
- 点、线段、箭头、圆、面的标签，以及「文字」对象，都可以是一段 note：多行、标题、列表、行内 / 块公式、引用、提示框、代码。
- 画布上双击标签（或文字对象）→ 原地弹出 note 编辑器，`/` 插块、选中文字出浮动工具条，和写 note 一样；点外面或 ⌘↩ 提交，Esc 也提交（防丢内容；块选中时 Esc 归编辑器）。
- 只写了一行纯文字的旧标签照旧单行显示；双击编辑一次后升级成卡片。

**复用与边界（读代码确认）**：
- 编辑：复用 `text-editing.Host`（与画板文字节点同一个编辑器），**不复用 canvas-text-node 的 EditOverlay**——它是全局单例浮层，画板视图也挂着，同窗口开着画板时会弹出两个编辑框。卡片编辑浮层由全屏面板自己挂。
- 菜单：用自己的 viewId（`math-visual-card`）注册斜杠菜单 / 浮动工具条（菜单内容按 viewId 注册，不注册就弹空菜单）；斜杠项过「编辑能插 ⊆ 渲染能渲」闸。该闸从 `views/graph-canvas-view/slash-render-gate.ts` 挪到 `lib/atom-serializers/svg/slash-render-gate.ts` 共用，画板原文件留作薄包装（画板仍额外屏蔽折叠列表）。
- 显示：复用 `lib/atom-serializers/svg` 把卡片画成 SVG（文字转路径），嵌进同一张 Mafs SVG → 退出全屏的缩略图自带卡片，X 长文导出不变。
- ~~层级：编辑期间给 body 加类把浮层抬到全屏之上~~ —— **无效，已撤**。真因（用户截图「没有 block、没有 slash」后查出）：交互浮层（右键 / 斜杠 / 手柄 / 浮动工具条 / popup）挂在 workspace 的 OverlayFrames 里，全屏打开时整个 workspace 层 `display:none`，浮层根本不存在，抬层级没用。修法（shell 层，通用）：全屏打开时这组浮层改由 FullscreenOverlayBinding 挂、workspace 那组同时不渲染（任何时刻只一套；挂两套 = SlashMenuBinding 的 capture 键盘监听双触发，一次回车执行两次），并在全屏层里统一排到最上面。
- 卡片编辑 = note 编辑：块手柄打开，照 diglot 语义面（`mind-semantic-menus.ts`）注册完整一套斜杠 / 手柄 / 浮动工具条；手柄「转换为…」也过同一道渲染闸（handle-turn-X ↔ slash-turn-X 同表，未登记的拦下）。编辑框收紧成卡片尺寸（`.krig-pm-host` 原是整页样式：左 48px / min-height 200）。

**已知缺口**：渲染器还画不了表格和图片，所以斜杠菜单里暂时不会出现这两项；补渲染器后自动放开（画板同时受益）。

**以后**：表格数据 → 图上的点、公式 → 曲线（「互相转换」的联动），与时间滑块一起做。

## 五、验收

**判据（AI 对账）**
1. 老文档：没有 `shapes` / `frames` 的 mathVisual 块打开、编辑、导出与改动前完全一致（`thumbnail` 照旧）。
2. 样本题三帧按第二节做出来：帧 1 只有 Andy；帧 2 多出 Betsy 与 Andy 虚影；帧 3 多出圆与打叉虚线；两个方向同比例尺。
3. inline 翻页不触发 Mafs 渲染；展开后三张图都在，各带那句原文。
4. 写错一个坐标表达式：对象列表那一行报错，其他对象照常显示。
5. X 长文内嵌这个块：拿到的是完整图（帧 3）。

**单测（另一对话可跑）**
- 可见性判定纯函数：缺省 / 只有 from / from+to / 越界。
- 老数据归一化：缺字段时 `getDataFromNode` 结果与现在逐字段相等。
- 守卫要能变红：故意把可见性判定改成恒真，单测必须失败。

**人工**：重启 app，在 note 里照第二节做一遍样本题，翻页、展开各看一眼。
