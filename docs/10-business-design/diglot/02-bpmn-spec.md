## 1. ⭐⭐ 这个图种的语义骨架:**有向图**

**与 mind 的根本差别,不是「换个文法」而是换模型:**

| | mind(`01`) | ⭐ bpmn(本文) |
|---|---|---|
| 骨架 | **树**(`parent` 是真相) | ⭐ **有向图**(边是主结构) |
| 边的性质 | 联系线:树之外的**附加**关系 | ⭐ **序列流:骨架本身** |
| 有汇合吗 | ❌ 一个节点只有一个父 | ✅ **多条分支可合并** |
| 有循环吗 | ❌ 树无环 | ✅ **允许回边** |
| 节点类型 | 同质(都是 Node) | ⭐ **异质**:事件/活动/网关**语义不同** |

> ⚠️ **所以不要试图让 bpmn 复用 mind 的 `parent` / 树推导规则。**
> 这不是实现偷懒的问题,是**模型本身不同**。

## 2. ⭐ 「按工业标准」意味着什么

用户 2026-09-09:「要**按照工业标准**来建设这两个图 mind/bpmn。」

| | 够用就行 | ⭐ 工业标准 |
|---|---|---|
| 图元 | 自定义几个方块 | **BPMN 2.0 规定的图元集** |
| 文件 | 自定义格式 | ⭐ **能导入导出 `.bpmn`(XML)**,与 Camunda / Visio / bpmn.io 互通 |
| 语义 | 我们说了算 | **token 流转语义由标准定死** |
| 校验 | 无 | **结构合法性**(网关成对、无悬空流、起止齐备) |

⭐ **互通性是工业标准的核心价值** —— 用户能把别处画的图拿进来,也能拿出去。
**这一条决定了数据模型不能自己发明。**

## 3. 起步:先兼容 mermaid `flowchart`

按 `00-diglot-core.md` §2,前期兼容 mermaid 语法当检验素材。

⭐ **仓库已有 mermaid `Flowchart` 模板**(`mermaid-renderer.ts`):

```
graph TD
  A[开始] --> B{条件}
  B -->|是| C[操作]
  B -->|否| D[跳过]
  C --> E[结束]
  D --> E
```

⭐ **mermaid flowchart 与 BPMN 的映射天然接近**:

| mermaid | BPMN |
|---|---|
| `A[方框]` | Task(活动) |
| `B{菱形}` | Gateway(网关) |
| `C((圆))` | Event(事件) |
| `-->` | SequenceFlow(序列流) |
| `-->|标签|` | 带条件的序列流 |

⚠️ **但 mermaid flowchart 不是 BPMN**,以下表达不了(记账,后期扩展):
泳道(Pool/Lane) · 网关的具体类型(排他/并行/包容) · 边界事件 ·
子流程 · 消息流 · 数据对象

**分期**:

```
前期  兼容 mermaid flowchart —— 导入现成图当检验素材,验证双向同步引擎
后期  向 BPMN 2.0 完整图元 + .bpmn XML 互通扩展
```

## 4. 实体清单(BPMN 2.0 对齐)

### 4.1 FlowNode(流程节点)—— ⭐ 异质,类型即语义

```
Event      事件   起点/终点/中间   圆形
Activity   活动   要做的事         圆角矩形
Gateway    网关   分叉/汇合        菱形
```

| 属性 | 层 | 说明 |
|---|---|---|
| `id` | S | 稳定标识,三面 join 键;⭐ **导出 .bpmn 时即 XML id** |
| `kind` | S | ⭐ `event` \| `activity` \| `gateway` —— **有语义的类型,不是形状** |
| `subtype` | S | 见下方词表。⚠️ **subtype 决定执行语义,不许当样式处理** |
| `name` | S | 节点名(图上显示) |
| `content` | S | 富文本备注。⭐ KRIG 中即 note block —— **公式、图片、链接天然承载** |
| `pos` | G | 坐标。⭐ **存在即 pinned**(同 mind) |
| `size` | G | ⚠️ BPMN 节点有标准尺寸,但允许覆盖 |
| `color` | G | 样式 |

**subtype 词表(v0 最小可用集)**:

| kind | subtype | 语义 |
|---|---|---|
| `event` | `start` / `end` | ⭐ **起止必备** —— 校验规则依赖它 |
| `event` | `intermediate` / `boundary` | 后期 |
| `activity` | `task` | 普通活动 |
| `activity` | `subprocess` / `call` | 后期 |
| `gateway` | ⭐ `exclusive`(排他,X) | **走且仅走一条** |
| `gateway` | ⭐ `parallel`(并行,+) | **全部同时走** |
| `gateway` | `inclusive`(包容,O) | 后期 |

⚠️ **v0 实现 `exclusive` 与 `parallel` 两种网关** —— 它们覆盖绝大多数流程,
且**语义正交**(二选一 vs 全都要),能把网关机制验充分。

### 4.2 ⭐ SequenceFlow(序列流)—— 骨架本身

⚠️ **与 mind 的 Edge 性质根本不同**:这里边是**主结构**,不是附加关系。

| 属性 | 层 | 说明 |
|---|---|---|
| `id` | S | 稳定标识 |
| `source` / `target` | S | ⭐ **必填且强制有向**。⚠️ 不像 mind 可以「渲染弱化箭头」—— **BPMN 的方向是语义** |
| `condition` | S | ⭐ 条件表达式(从排他网关出来的分支必须有) |
| `label` | S | 显示标签(如「是」「否」) |
| `waypoints` | G | 手动走线,稀疏纪律同 pos |
| `style` | G | 线型/色 |

⚠️ **`condition` 是 S 层不是 G 层** —— 它**改变流程走向**,是语义不是外观。

### 4.3 Lane / Pool(泳道)—— ⚠️ v0 登记不实现

BPMN 的泳道表达「**谁负责这一步**」。

⚠️ **v0 登记名称、不实现** —— 理由:泳道是**容器**,会牵动布局算法
(节点必须落在自己的泳道内),而 v0 的重点是**先把双向同步引擎验通**。

### 4.4 Document

| 属性 | 层 | 说明 |
|---|---|---|
| `type` | S | `bpmn` —— 文档类型 = 解释器选择 |
| `name` | S | 流程名 |
| `theme` | G | 主题/配色 |

## 5. ⚠️ 结构校验(工业标准要求,mind 没有的一层)

⭐ **mind 宽容(级别跳跃不报错);bpmn 必须校验** —— 因为流程图有**对错**。

| 规则 | 说明 |
|---|---|
| **起止齐备** | 至少一个 `start`、至少一个 `end` |
| **无悬空流** | 序列流的 source/target 必须都存在 |
| ⚠️ **无孤立节点** | 除 start 外每个节点都要可达 |
| ⚠️ **排他网关的分支要有条件** | 否则走向不确定 |
| **并行网关应成对** | 分叉了要合并(⚠️ 标准允许不合并,但**多半是错的** → **警告不报错**) |

⚠️ **校验失败怎么办**:按 `00-diglot-core.md` §8 的 **C6 错误隔离** ——
**标出来,不阻止编辑,画布保持可用**。

> ⭐ **流程图画到一半必然是不合法的**(刚放了 start 还没连线)。
> **校验是「提示」不是「门禁」** —— 否则没法画。
> 只有**导出 .bpmn / 交给执行器**时才是硬门槛。

## 6. 投影对照表

| 模型概念 | mermaid flowchart | KRIG block | .bpmn XML(后期) |
|---|---|---|---|
| 活动 | `A[名字]` | block | `<task>` |
| 网关 | `B{名字}` | block | `<exclusiveGateway>` |
| 事件 | `C((名字))` | block | `<startEvent>` |
| 序列流 | `A --> B` | `flows` 三元组 | `<sequenceFlow>` |
| 条件 | `A -->|是| B` | 边的 condition | `<conditionExpression>` |
| 备注 | ❌ 表达不了 | block 余部 | `<documentation>` |
| G 层 | ❌ | 属性三元组 | `<BPMNDiagram>` |

⭐ **最后一列值得注意**:BPMN XML **自己就分两层** ——
`<process>` 是语义,`<BPMNDiagram>` 是图形。
⭐ **这与 diglot 的 S/G 分层天然同构** —— **标准本身就认同这个分法**。

## 7. 落笔矩阵

| 操作 | S 层 | G 层 | 画布 |
|---|---|---|---|
| 改节点名 | 一处 update | 零 | 该节点重绘 |
| 连线 | ⭐ **一条 SequenceFlow** | 零 | 即时 |
| 改边的条件 | ⭐ **一处 update**(是语义) | 零 | 边标签重绘 |
| 拖动节点 | 零 | 一条 pos 条目 | 即时 |
| 拖动边的拐点 | 零 | 一条 waypoints 条目 | 即时 |
| 改网关类型 | ⭐ **subtype update**(改语义) | 零 | ⚠️ **图元换形** |
| 改颜色 | 零 | 该条目更新 | 重绘 |

⚠️ **注意两行的差别**:
「改网关类型」落 **S 层**(它改变流程语义),
而 mind 的「改形状」落 **G 层**(纯外观)。**同样是「换个样子」,归属不同。**

## 8. 画布操作(对齐 bpmn.io 惯例)

⚠️ **不照搬 XMind** —— 流程图的肌肉记忆来自 bpmn.io / Visio,与导图不同。

| 操作 | 触发 | 落笔 |
|---|---|---|
| 放节点 | 从图元面板拖入 / 双击空白 | S:一处插入;G:pos |
| ⭐ **连线** | **从节点边缘拖到目标节点** | S:一条 SequenceFlow |
| 改连线端点 | 拖动线的端点 | S:source/target 变更 |
| 删除 | `Delete` | S:节点 + **连带删除悬空的流** |
| 改节点类型 | 选中后类型面板 / 右键 | S:kind/subtype 变更 |
| 编辑名字 | 双击节点 | S:name update |
| 编辑备注 | `F4` | S:content(**note block 编辑器**) |
| 边条件 | 选中边后属性面板 | S:condition update |
| 拖动节点 | 拖动 | G:pos |
| ⭐ **自动布局** | 工具栏 | G:批量 pos ⭐ **走 ELK `layered`** |
| 缩放 / 平移 | 同 mind | 会话(不持久) |

⭐ **自动布局是 bpmn 比 mind 更需要的功能**:流程图节点多、连线交叉,手工摆很累。
✅ **`graph-layout` capability 的 `layered` 算法就是为此设计的**,
输入格式 `{nodes, edges:[{id, source, target}]}` **与本模型天然吻合**。

## 9. ⚠️ 画板缺口(本图种阻塞项)

`00-diglot-core.md` §9.1 列的三个缺口,**对 bpmn 全是硬阻塞**:

| 缺 | 对 mind | ⭐ 对 bpmn |
|---|---|---|
| **箭头不渲染** | 可接受(联系线可弱化箭头) | ⚠️⚠️ **致命** —— 流程图没箭头就不是流程图 |
| 边的方向语义 | 可接受 | ⚠️ **必需** —— 方向是语义 |
| 边标签 | 想要 | ⚠️ **必需** —— 网关的「是/否」靠它 |

> ⭐ **所以 bpmn 开工前必须先补这三样。** mind 可以先跑起来,bpmn 不行。
> 这是排期上的硬约束。

## 10. 本图种专属断言

⚠️ 通用断言(C1–C9)见 `00-diglot-core.md` §8。**以下是 bpmn 独有的**:

- **B1 有向性**:边的 source/target ⭐ **不可互换**;导出后再导入,方向一致
- **B2 汇合成立**:两条边指向同一节点 → 模型正确表达,**不被当成「重复边」去重**
- **B3 回边允许**:构造一个环,**模型接受、画布能画、序列化正确**(⚠️ 树模型做不到这条)
- **B4 校验是提示不是门禁**:半成品流程图(只有一个 start)**画布仍可用**,只标警告
- **B5 subtype 落 S 层**:改网关类型 → **S 层 update**,G 层零变更,图元换形
- **B6 .bpmn round-trip**(后期):导入 `.bpmn` → 编辑 → 导出 → **能被 bpmn.io 打开**
