## 1. 一句话

> **站点知识 = 数据(说明书),不是代码。通用引擎照说明书收数据、对账、操作、核对;
> 对不上就进入诊断:AI 自己看日志、截图、原始数据,找出原因,改说明书,拿历史样本回归,留档生效。**
> **先在 X 上把标准建起来,逐步迭代;第二个网站不急。**

## 2. 先说清楚能证明什么、不能证明什么

| | 能不能证明 | 怎么证明 |
|---|---|---|
| **浏览器收到的,我全解析了、全存了** | ✅ 能,且与站点无关 | 收到 ↔ 解析 ↔ 入库 三方逐条对 id |
| **页面显示给人看的,我都采到了** | ✅ 能(抽样 / 诊断时) | 截图 ↔ 库 对照(§6) |
| **世界上存在的,我全拿到了** | ❌ 不能 | 服务器决定给什么:推荐 / 排序 / 限流 / 隐藏 / 删除;无限流没有总数 |

> 实例:@Hanbaoge_ 推文 2111267261369782336,X 连 `from:` 搜索都不返回 —— 不是我们漏,是 X 没给。
> **设计、界面、报告里都不许承诺第三行。**

## 3. 结构

```
  语音 / 手势 / 文字指令            (将来)
        │  「关注他」「把这一页采下来」「回他一句」
        ▼
  意图 → 动作(语义名)
        │
  ┌─────┴──────────────── 通用引擎(代码,写一次)───────────────────┐
  │  采集  · 收下一切网络响应 / DOM / 无障碍树                        │
  │  对账  · 收到 ↔ 解析 ↔ 入库(常开)                              │
  │  操作  · 按「角色 + 名字」找控件 → 动作 → 核对预期变化            │
  │  诊断  · 日志(终端 / DevTools)· 截图 · 原始数据 · 本机或云端 AI │
  │  样本  · 对不上就把现场整份存下                                   │
  └─────┬───────────────────────────────────────────────────────────┘
        │ 读
  站点说明书(数据,每站一份,带版本)  ← AI 起草 / AI 修订 / 人确认
        │
  样本库(现场快照,回归用)  ·  修改档案(列表,可回溯,定期归档)
```

与 `01-contract.md` 的关系:**说明书就是 §14 adapter 的「数据化」**。
现在 adapter 是代码(`x-pages.ts` 语义页面表、`x-anchors.ts` 锚点表、`x-timeline-audit.ts` 载荷解析、`x-dom-scripts.ts` 页面脚本);
本设计把其中**「解释」的部分**挪成数据,引擎照着执行。底座边界(§2「底座不做判断」)不变。

## 4. 站点说明书

### 4.1 写什么

| 段 | 回答什么 | X 现在在哪(代码) |
|---|---|---|
| **识别** | 这个 URL 是哪一类页面(搜索 / 个人主页 / 单篇 …) | `x-pages.ts` identify |
| **导航** | 语义页面名 → URL 模板 | `x-pages.ts` resolve |
| **数据** | 哪个接口带数据;条目在哪、id 是哪个字段;游标在哪、哪个是「往下」;有没有总数;哪些接口是噪音 | `x-timeline-audit.ts`、`x-page-ledger.ts`、`x-pages.ts` 噪音表 |
| **显示** | 截图上一条条目长什么样、能看到哪几个字段(作者 / 正文开头 / 时间)—— 截图对照用 | 无(现在靠人右键查库) |
| **控件** | 语义动作 → 按「角色 + 名字」找控件 → 点完应变成什么 | `x-dom-scripts.ts`(follow / like / sendReply)写死 testid |
| **领域映射** | 条目 → 本站领域对象(推文 / 人)的字段对应 | `x-timeline-audit.ts` toRecord |

### 4.2 样子(10-18 示意;P2 定稿的格式见 §4.4)

```yaml
site: x.com
version: 14
pages:
  search:
    match: { url: "^https://x\\.com/search\\?" }
    data:
      endpoint: { url: "/i/api/graphql/[^/]+/SearchTimeline" }
      items:    { at: "$..instructions[*].entries[*]", id: "content.itemContent.tweet_results.result.rest_id",
                  kinds: { tweet: "content.itemContent.tweet_results", user: "content.itemContent.user_results" } }
      cursor:   { at: "$..entries[?(@.content.cursorType=='Bottom')].content.value", direction: down }
      noise:    ["fleets/v1/avatar_content", "1.1/graphql/viewer_context.json"]
    display:
      item:     { role: article, fields: [author_handle, text_head, time] }
  profile:
    actions:
      follow:   { find: { role: button, name: "^Follow$" },     expect: { role: button, name: "^Following$" } }
      unfollow: { find: { role: button, name: "^Following$" }, then: { role: button, name: "^Unfollow$" },
                  expect: { role: button, name: "^Follow$" } }
```

**铁律**:

1. ⭐ **说明书只有声明,没有可执行代码**(路径表达式、正则、角色 + 名字)。
   AI 改说明书 = 改数据,不能注入脚本 —— 这是让 AI 自己改它的安全前提。
2. ⭐ **每次修改是一个新版本**,带「为什么改 + 依据样本 + 回归结果」,进修改档案(§9);可回滚到任一版本。
3. 说明书表达不了的(真需要计算的),留在 adapter 代码里,**显式登记**为「说明书外」——
   数量本身就是指标:越少说明这套格式越够用。

### 4.4 ✅ P2 定稿的格式(2026-10-19)

**文件**:每站一个目录,X 的在 `src/modules/x/manual/`:`x.manual.json`(当前版)· `history/v0001.json`(每版快照)· `changes.json`(修改档案主列表)· `archive/YYYY-MM.json`(按月归档)。
**引擎**:`src/platform/main/web-capability/manual/`(纯函数,renderer / main 都用;能力层「不认识站点」守卫自动覆盖)。

**路径表达式**(§12 #2,我定的,理由是效果):`$变量.键.键`,只有末尾可带 `[*]`;取值可写 `{first|firstObject|firstString: [路径…]}`;
条件只有 `isObject / isArray / nonEmpty / equals / contains / matches / any / all / not`。
- 不用 JSONPath:常见库的过滤表达式 `?(@.x=='y')` 靠 eval 实现 = 把代码塞进数据,违反铁律 1
- 加载时**逐条自检**(`checkManual`):变量在那个位置有没有、`[*]` 该不该有、正则编不编得过、字段齐不齐 —— 写错当场报「哪一段哪一条」,不等真机跑出 0 条
- 每条规则 / 噪音带 `why`(JSON 没注释,AI 改之前要能看懂来历)
- 引擎源码有守卫:零处 eval / new Function / 动态 import

**数据段现有**:`census`(容器 → 条目 → 规则:cursor / item / group,不认识的照样计数留名)· `orderedByTime`(判翻页方向的页)· `noise`。
**说明书外**(铁律 3,登记在 JSON 的 `outside`):翻页实际挑游标(DAAD 兜底是启发式)· 哪些响应算这一页(接口判据)· 推文页夹的人记「推荐的人」· 领域映射 / 条目时间 / 截断判据。

**修改档案**(§9;§12 #3 用户 10-19 选「按月归档」):`node scripts/manual.mjs list|show|diff|check|record|rollback|archive <目录>`。
对比由工具从快照算,不手写;举手(`--raised`)的不归档、主列表置顶;回滚也是一次新版本、也记档。守卫 `tests/modules/x-manual-archive.test.ts`:改了说明书不记档 / 手改对比 / 版本跳号 → 红。

**验收**(§11 P2):
1. 基线:dev 收件箱指令带 `sample` 存每页原始载荷到本机 `krig-data/x-dev/samples/`(不进 git);新增 `userList` 指令采名单页。10-19 存了搜索最新 / 热门、主页帖子 / 回复 / 转发、followers、following 共 27 页
2. 新旧并跑:`tests/modules/x-manual-parity.test.ts` —— 手造 4 份 + 随机 1 万份(每个分支都撞到 >50 次)+ 真实样本逐字段一致;旧实现冻结在 `tests/modules/x-legacy-census.ts`
3. 真机并跑:两套账同时算,报告写「说明书账 4 页逐页与旧账一致」(搜索)/ 转发 3 页一致 → 切换为照说明书清点
- ⚠️ 真实样本里**没撞到广告和墓碑**(连 bitcoin「热门」也没有);这两类目前只由手造 + 随机载荷覆盖
- ⚠️ followers / following 第一页 70 人 X 就发了 `TimelineTerminateTimeline`(两个名单都是)—— 与 P2 无关,未查

### 4.3 控件为什么用「角色 + 名字」

浏览器为每个网页算一棵**无障碍树**(给读屏软件用):每个控件有角色(按钮 / 输入框 / 链接)和名字(「关注」「发布回复」)。
- 几乎所有网站都有,而且网站为了无障碍合规**不敢乱改**
- `data-testid` 是开发者内部用的,随时可删 —— X 已在 2026-09 把**未登录页**的 testid 全删(见 `x-anchors.ts` 注释)
- 名字随界面语言变(Follow / 关注)→ 说明书里名字写成正则,或按语言分组

取法:CDP `Accessibility.getFullAXTree`(**本仓尚未接**)。

## 5. ⭐ 日常诊断能力(用户 10-19:「AI必须有能力执行日常的诊断方式-- terminal log/devtools log」)

**现在的缺口**:诊断全靠用户当传声筒 —— 截图、复制终端输出、开 guest DevTools 看 console。
AI 自己既看不到终端,也看不到任何一个网页的 DevTools。自修闭环的第一块砖是**让 AI 能自己看现场**。

### 5.1 AI 要能读到的五样

| 现场 | 现状(10-19 查) | 要做的 |
|---|---|---|
| **终端日志**(主进程 `console.*`) | ❌ 只打到启动 app 的那个终端,不落盘 | 主进程 console 同时写文件(按天分片 JSONL,与 `fs-trace-sink` 同口径);带进程 / 时间 / 级别 |
| **DevTools 日志**(每个网页的 console / 报错) | ❌ 只在那个网页自己的 DevTools 里(记忆 `feedback-log-where-the-human-looks`);只有剪藏一处监听了 `console-message` | 每个受管网页的 `console-message` + 页面报错 + 加载失败 → 写文件,带 pageId / URL |
| **能力层留痕**(goto / harvest / 对账 / 动作) | ✅ `web-trace/lifecycle/*.jsonl` 已有 | 照用 |
| **运行黑匣子**(卡顿 / 内存 / 进程) | ✅ `health/*.jsonl` + `scripts/health-report.mjs` 已有 | 照用 |
| **原始网络响应** | ⚠️ L-raw 已建已测,**零消费者**,磁盘上无数据 | 接上(§7) |

再加两样**按需取**的:**截图**(§6)、**无障碍树 / DOM 快照**。

### 5.2 诊断怎么被触发

| 触发 | 例 |
|---|---|
| 对账对不上 | 某页 X 列了 20 条,解析出 19 条 |
| 动作没出现预期变化 | 点了关注,按钮没变成「正在关注」 |
| 日志里出现异常 | 网页 console 报错、接口 4xx/5xx、能力层 failed |
| 人提出 | 用户:「这个不对」/ 右键「查库」查不到 |
| 定期体检 | 抽样截图对照(§6.3) |

### 5.3 诊断包

一次诊断收拢成一个包(也就是一个样本,§7):相关时间窗的终端日志 + DevTools 日志 + 留痕 + 原始响应 + 截图 + 对账结果。
**AI 拿到的是整份现场,不用再问人要。**

## 6. 截图对照 —— 诊断的重要方法(用户 10-19:「把解读当作需要诊断时的重要方法」)

### 6.1 为什么需要

收到 / 解析 / 入库三方都来自**同一条数据通道**。网站换了一种条目格式、解析器不认识时,三方可能**一起错、错得一致**,对账发现不了。
截图是**人眼看到的**,走另一条路 —— 它是独立的真相源。

这就是用户 10-16 定的「左边 X 原页、右边查库」抽检办法(`feedback-collect-verify-side-by-side`),把「人来看」换成「AI 来看」。

### 6.2 怎么对

```
截图 → 看图模型按说明书「显示」段列出这一屏的条目(作者 / 正文开头 / 时间)
     → 与这段时间入库的条目按关键字段匹配
     → 三个桶:
         截图有、库里没有   → 漏采(数据通道)
         库里有、截图找不到 → 多采 / 对错位(或只是还没滚到 —— 要看位置)
         两边都有、内容不符 → 解析错
```

### 6.3 什么时候截

**定位:诊断手段,不是常开的门槛。** 需要诊断时自动截(§5.2 的触发),平时只做低频抽样体检。

| 情况 | 截图频率(我的初值,可调) |
|---|---|
| 平时(三方对账干净) | 抽样体检:每 N 屏截 1 张 |
| 进入诊断 | 出问题那一屏 + 前后若干屏 |
| 说明书刚改过 | 前若干页每屏都截,确认改对了 |

### 6.4 本机 AI 与云端 AI(用户 10-19:「这个看授权,不能绝对化,云端AI是帮助训练本地模型的关键」)

| | 用在 | 授权 |
|---|---|---|
| **本机看图模型** | 平时抽样、常规诊断 | 默认可用 |
| **云端模型** | 本机看不懂 / 判断不一致时升级;**给本机模型产出训练样本**(云端的判断 + 人确认 → 本机学) | ⭐ **按授权**:授权粒度(按站点 / 按页面类型 / 按次)P4 定;每次发了什么进档案 |

- 授权**不写死成「绝不发」**,也**不默认全发**;没授权时诊断照做,只是停在本机能力内并说明「这里需要云端看」
- 云端判断与本机判断不一致的样本,是训练本机模型最值钱的数据 —— 单独标出来

### 6.5 边界

- **截图只有一屏**:长列表顺着滚动一屏一张(滚动采集本来就在一屏屏走)
- **看图会看错**:截图结论标「AI 判断」;改说明书要有回归支撑(§8),不凭一次看图

## 7. 样本库

**一个样本 = 一次诊断的完整现场**(§5.3 的诊断包)+ 当时的说明书版本 + 结论:

| 内容 | 来源 | 现状 |
|---|---|---|
| 原始网络响应 | L-raw(`01-contract.md` §13) | ⚠️ **已建未接** —— `FsRawSink` 写好、测过,**零处 new** |
| 终端 / DevTools 日志(时间窗) | §5.1 | ❌ 未接 |
| 截图 / 无障碍树 | §6 / §4.3 | ❌ 未接 |
| 对账结果 | 引擎 | ⚠️ X 有(`x-page-ledger.ts`、`x-audit/x-scroll-*.txt`),X 专用 |
| 结论(真问题 / 误报 / 已修于版本 N) | AI + 人 | ❌ |

**回归** = 拿某版说明书,对样本库**全部**样本重跑「解析 + 对账」,看:
- 原来对不上的,现在对上了吗(修好了)
- 原来对得上的,现在还对得上吗(没弄坏)

> 这正是 `01-contract.md` §13.3 说的「最值钱的一条」:把「改进解析」从**等数据攒够**变成**立刻可验证**。

## 8. 自修闭环

```
① 发现:§5.2 任一触发
② 诊断:自动收诊断包(日志 + 留痕 + 原始响应 + 截图);本机 AI 看,需要且有授权时升级云端
③ 定因:例「截图第 3 条是带投票的推文,原始数据里类型名叫 xxx,说明书 kinds 里没登记」
④ 提案:AI 写说明书修改(新版本 + 原因 + 依据样本)
⑤ 回归:新版本对全部样本重跑 —— 修好的 / 弄坏的 都列出来
⑥ 生效:按 §10 授权 —— 读方向回归全过即生效;写方向等人确认
⑦ 留档:进修改档案(§9)
```

**修不好怎么办**:回归不过、或同一问题修了几次还在 → **停,举手给人**(档案里标红 + 诊断包链接),不反复试。
(`feedback-pdca-close-the-loop`:停止由数据判据,不由猜的次数。)

> 10-18 初稿曾设「同一问题 ≥3 个样本才改」的门槛;用户 10-19 改为**以诊断为中心**:
> 出问题就诊断,证据靠诊断包(日志 + 截图 + 原始数据)和回归,不靠攒样本数。

## 9. 修改档案(用户 10-19:「留档/列表,方便回溯,定期归档。」)

## 10. 授权:读写分开

| 改的是 | 风险 | 生效方式 |
|---|---|---|
| **读**:识别 / 数据 / 显示 / 领域映射 | 最坏采错,可重采、可从 L-raw 重算 | 回归全过 → **自动生效**,进档案,可回滚 |
| **写**:控件 / 动作 | 会在网站上留下痕迹(关注 / 留言 / 点赞) | **人确认后生效**;准确率上去后再放开自动 |
| **发云端** | 截图 / 日志可能含隐私 | **按授权**(§6.4) |

> 写方向沿用用户 10-17 定的求关原则:「AI 给出建议,我来修正,准确率提升后开启自动化」;
> 以及 10-10 取消红线时的前提:节奏限制 / 异常即停 / 动作留痕 / 执行后核对(`project-x-write-redline-cancelled`)。

## 11. 分期 —— 先在 X 上建标准(用户 10-19:「先继续完善x的部分,但建立标准,逐步迭代」)

| 期 | 做什么 | 验收判据 |

| **P3 样本库 + 回归** | 接 L-raw;诊断包落成样本;回归命令 | 注入一个解析缺陷 → 诊断包留下 → 修好后回归显示「修好 1 / 弄坏 0」 |

| **P5 AI 自修(读)** | 诊断 → 提案 → 回归 → 生效 → 留档 | 人为制造一处说明书过期,AI 修好且回归不坏,档案里看得到全过程 |
| **P6 控件说明书化** | 接无障碍树;follow / like / reply 从 `x-dom-scripts.ts` 挪进说明书 | 求关三动作在说明书驱动下真机跑通,结果与现在一致 |
| 以后 | 第二个网站(验「新增基础设施 = 0」);语音 / 手势 | 用户定时机 |

X 每次出问题,现在都要用户截图、复制日志;有了它,这一步就省了。它也最独立,不碰现有采集逻辑。
