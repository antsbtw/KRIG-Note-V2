## 1. 用户原话(定方向的几句)

- 起因(看到一条「每天用 AI 出稿、回评论、留有价值的话」的帖子):「是否应该提供一个我和人工智能讨论的窗口,逐步优化我的x工作台?因为现在获取信息和发送信息的能力在完善了。请先讨论,再考虑如何构建。」
- 顺序:「先构建基础组件,让AI可以调用工作台的任何功能,从输入、控制、输出三个内容,另外把一些基础工作集约化;最后才是通过自然语言和AI沟通,Gemma可以向大语言模型请求指导。由我来选定最后的建议并批复完成。不讲具体,讲构建框架如何实现,细节最后再定。」
- Gemma ⇄ 大模型:「这个交互方法先明确 —— 通过web端进行交互哦。」
- 范围:「这是本末倒置,先一切皆可为,后面才收紧。而不是先收紧,再放宽。过度约束,一事无成。」
- 发给大模型的数据:「和上面是一个道理」(不预设边界)。

## 2. 分层(从下往上建)

```
⑤ 对话窗口        人用自然语言提问 / 下指令 —— 只是入口,不带来新权限
④ 提案与批复      AI 想改的任何东西都成「提案」→ 人挑选 / 修改 / 批复 → 才执行
③ AI 分工         Gemma(本地,高频小事)⇄ 大模型(经 AI 网页对话,策略与指导)
② 集约化          基础工作打包成可组合的流程模板 + 统一调度 + 重启不丢的队列
① 能力目录        一切功能登记一次:输入 / 控制 / 输出
   统一执行器      所有调用同一道关:前置检查 · 额度 · 网页占用 · 留痕
────────────────────────────────────────────────────────────
⓪ 现有底座        网页能力层(page/net/dom/input/manual)· 采集写库 · 动作记录 · 搜索额度账本 · 节奏自调 · AI 网页收发
```

### ① 能力目录 + 统一执行器
- **一切皆可为**:工作台所有功能、任意网页的通用操作(打开 / 读 / 滚 / 点 / 输入)、库里的数据都登记成能力;不预先划「只登记 X」「只读不写」。
- 每个能力自带:说明(给 AI 读)、输入 / 输出形状、类别(输入 / 控制 / 输出)、前提、花费(如搜索页数)。
- **按钮、定时任务、AI 走同一个目录、同一个执行器** —— 不留暗道;AI 能做的 = 人能点的。也兑现 01 号文档「button 不该是黑盒」。
- 执行器每次调用写执行记录(01 号文档缺的「执行记录表」):谁发起、输入、结果、依据、耗时。
- 雏形:`modules/x/x-dev-inbox.ts`(JSON 指令 → 结果)就是这一层的样子,只是白名单、只给开发用。

### ② 集约化
- 流程 = 能力按步骤组成,每步写明吃什么、产出什么(01 号文档的 Template)。
- 例:求关一人、互动一人、每天三件事(查回关 → 关系采集 → 采互动)、配方搜索。
- 统一调度(现在各自 setInterval)+ 跨重启队列(现在全在内存)。
- 01 号文档定的「可重组步骤、不做分支」照旧;要判断走哪条的,交给 ③。

### ③ AI 分工 —— 大模型通过 web 端
- **Gemma(本地 Ollama)**:草拟、分类、在规则内挑选、按流程调用能力。
- **大模型 = app 里已登录的 AI 网页(Claude / ChatGPT / Gemini)**,不走 API:Gemma 或执行器把问题 + 需要的数据贴进 AI 网页、发送、读回答。
- 现成零件(2026-10-22 盘点):
  - `platform/main/ai/ask-orchestrator.ts` `askAI(serviceId, prompt, targetWcId, timeoutMs)` —— 贴入 → 发送 → 等 SSE 回答 → 返回 markdown;**有代码、没有真机验证记录**,主界面只用「只发不等」的 `pasteAndSend`。
  - 回答读取:`interceptor.ts` SSE 抓取(Claude / ChatGPT 真机验过,Gemini 走 CDP)、`extractFullConversation` / `extractConversationTurn` 整段 / 单轮提取。
  - 约束(物理事实,不是我们定的):OS 级粘贴要求 AI 网页可见且有焦点。
  - 已知小 bug:`handlers.ts` 的 `AI_SSE_STATUS` / `AI_GET_LATEST_RESPONSE` 没传 wcId,改成每个网页一份抓取后恒为空。
- 请教时机、请教格式、回答怎么变成提案 —— 细节后定。

### ④ 提案与批复
- AI 产出的改动一律是提案:做什么、为什么(数据依据)、预期效果、调用哪些能力、能否撤回。
- 批复三档:单个动作 / 一批 / 长期规则(批一次,撤销前一直生效)。
- 批复后执行器执行并留痕;之后回看效果,喂给下一轮建议(跨执行的回路,02 号文档 §第5步)。

### ⑤ 对话窗口(最后做)
- ①~④ 之上的一个入口:提问 → 调输入类能力答;要做事 → 生成提案等批。

## 3. 贯穿规矩
- **先全开放、后收紧**:能力、网页、数据都默认可用;收紧只在真实问题出现后、带证据提出。
- 留痕、可解释、可撤销;故障必响(不静默兜底)。
- 自设规矩只提醒不拦;拦的只有真实故障和平台自身限制。
- 发到外部(X 发帖 / 点赞 / 留言 / 关注…)的动作由人批复,或落在人批过的长期规则内。
- 能力目录是平台层通用件;各模块往里登记自己的能力,删模块目录即卸载(可装卸原则)。
